# FITR_allInclusive
vibe-coded project to administrate course works and 3d model purchases

## Запуск бота

Все команды выполняются из корня проекта (папка с `requirements.txt`).

Первый раз (или после `git pull`, если менялся `requirements.txt`):

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Запуск:

```bash
source .venv/bin/activate
python -m bot
```

Бот работает, если в логе есть строка `Run polling for bot @...`. Остановить — `Ctrl+C`.

Одновременно может работать только один экземпляр бота: ошибка `TelegramConflictError`
значит, что он уже запущен где-то ещё. `.env` читается только при старте — после правки
перезапустите бота.

## Настройки (`.env`)

Файл `.env` в корне проекта, в git не попадает:

```
BOT_TOKEN=токен от @BotFather
ADMIN_IDS=111111111,222222222
MASTER_USERNAME=ник_мастера
PAYMENT_CARD=1234 5678 9012 3456
PAYMENT_IBAN=BY00 XXXX 0000 0000 0000 0000 0000
PAYMENT_RECIPIENT=Иванов Иван Иванович, ОАО «Банк»
```

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | Токен бота от @BotFather. **Обязательна.** |
| `ADMIN_IDS` | Числовые Telegram id мастеров через запятую. Всем им приходят карточки новых заказов, и любой из них может выставить счёт, отклонить заказ или сменить статус; карточки у всех мастеров обновляются одновременно. Свой id можно узнать у @userinfobot. Старое имя `ADMIN_ID` (один id) тоже работает. |
| `MASTER_USERNAME` | Ник мастера без `@` — **запасной** контакт: кнопка «💬 Связаться с мастером» даёт ссылку на него, только если `ADMIN_IDS` не задан. Обычно переписка идёт внутри бота. |
| `PAYMENT_CARD` | Номер карты для оплаты. Если не задан — способ «💳 Картой» клиенту не предлагается. |
| `PAYMENT_IBAN` | IBAN для оплаты переводом. Если не задан — способ «🏦 По IBAN» не предлагается. Наличные при получении доступны всегда. |
| `PAYMENT_RECIPIENT` | Получатель (ФИО, банк) — показывается клиенту под номером карты или IBAN. |

Обязателен только `BOT_TOKEN`; без остальных бот работает, но без уведомлений мастерам,
ссылки на мастера и реквизитов.

**Каждый мастер должен один раз нажать /start у бота** — иначе Telegram не разрешит боту
написать ему первым, и карточки заказов до него не дойдут (в логе будет предупреждение).

### Команды мастера

- `/orders` — список активных заказов (новые, ждут оплаты, печатаются, готовы к выдаче),
  новые сверху. Под списком кнопки «📋 №N» — открыть карточку заказа; у готовых к выдаче —
  ещё «📬 Выдать №N» (присылает карточку с подтверждением выдачи).
- `/orders all` — все заказы, включая отклонённые.
- `/order N` — прислать карточку заказа №N заново (например, если сообщение потерялось).
- `/activity` — сколько уникальных людей нажимали /start за последние 7 дней: по каждому
  дню и итог за неделю (дни — по Минску, запуски мастеров не считаются).

### Промокоды с сертификатов

Коды вписываются в `bot/catalog.py` в списки `FREE_PROMO_CODES` («печать до 200 г бесплатно»)
и `HALF_PROMO_CODES` («скидка 50%»), каждый в кавычках через запятую. После правки перезапустите
бота. Регистр, пробелы и дефисы не важны: `FITR-7K2Q-9XMD` = `fitr 7k2q 9xmd`. Делайте коды
длинными и случайными.

- **Клиент** вводит код на сводке перед подтверждением заказа: кнопка «🎟 Ввести промокод».
  Строка «Промокод: …» видна в сводке, в «📦 Мои заказы» и в карточке мастера (у мастера — ещё и
  сам код, чтобы сверить с сертификатом).
- **Каждый код одноразовый.** Использованные коды хранятся в таблице `promo_uses` и не
  освобождаются, когда выданный заказ удаляется из базы. Если мастер **отклонит** заказ, код снова
  начинает действовать (клиенту об этом пишется). Удалять код из `catalog.py` после использования
  не нужно.
- **Скидка 50%** применяется к счёту автоматически: и к расчёту по весу, и к «✏️ Своей сумме»
  (мастер вводит полную сумму, бот делит её пополам).
- **«Печать до 200 г бесплатно»**: при расчёте по весу до 200 г — 0 BYN, тяжелее — лишние
  граммы по цене за грамм + наценка за заполнение. Для разработки и «Своей суммы» бот только
  напоминает мастеру о сертификате — сумму (можно 0) мастер вводит сам.
- Заказ на **0 BYN** не ждёт оплаты: сразу уходит в печать.
- Защита от подбора: не больше 100 неверных кодов в час на клиента (`PROMO_MAX_ATTEMPTS`).

Проверить, использован ли код: `sqlite3 data/bot.db "SELECT * FROM promo_uses;"` (код хранится
без пробелов и дефисов, заглавными буквами).

### Проверка файла модели

Файл, который клиент присылает при заказе печати (и при замене файла в «📦 Мои заказы»), бот
проверяет не только по расширению (`.stl`, `.step`, `.stp`), но и по содержимому: STEP должен
начинаться с `ISO-10303-21;`, текстовый STL — со слова `solid`, у двоичного STL размер должен
сходиться с числом треугольников в заголовке. Переименованная картинка или пустой файл
отклоняются с просьбой экспортировать модель заново. Файлы больше 20 МБ (Telegram не даёт боту
их скачать) и файлы, которые не удалось скачать из-за сбоя сети, принимаются без проверки.
Файл, который прикладывает мастер в «🛠 Параметры печати», проверяется только по расширению.

### Адрес самовывоза

Если клиент выбрал «Самовывоз», на карточке заказа есть кнопка «📍 Адрес самовывоза» (на всех
этапах, кроме отклонённого). Договоритесь с клиентом о месте, нажмите кнопку и напишите адрес —
он появится в карточке у всех мастеров и у клиента в «📦 Мои заказы», а также в сообщении
«Заказ готов к выдаче». Отдельно клиенту адрес не отправляется. Изменить — нажать кнопку ещё раз.
Если клиент сменит доставку на Европочту, адрес самовывоза сбросится.

### Счёт и автоматический расчёт цены

«💳 Выставить счёт» на карточке заказа:

- если у заказа заданы **толщина слоя и заполнение** (клиент выбрал их при заказе печати или
  мастер задал через «🛠 Параметры печати») — бот просит **вес модели из слайсера** и считает:
  `вес × цена за грамм (по слою) + наценка за заполнение`, итог округляется **вверх до 10 копеек**.
  Дальше кнопки: [✅ Выставить X BYN], [✏️ Своя сумма], [⚖️ Другой вес];
- если параметров нет (разработка без параметров) — мастер вводит сумму вручную.

Для заказа на разработку расчёт покрывает только печать — стоимость разработки добавьте через
«✏️ Своя сумма». Клиент видит в счёте строку расчёта, если сумма выставлена по формуле.
Цены (`LAYER_PRICES`, `INFILL_SURCHARGES`), округление и максимальный вес — в `bot/catalog.py`:
меняете там, меняется и прайс, и расчёт.

### Переписка с клиентом

Переписка идёт внутри бота: одно сообщение — одно нажатие кнопки (текст, фото или файл).

- **Клиент** пишет через «💬 Связаться с мастером» → выбирает заказ (или «Общий вопрос») →
  сообщение приходит **всем мастерам** с кнопкой [✍️ Ответить].
- **Мастер** отвечает кнопкой [✍️ Ответить] под сообщением клиента или через
  `/orders` → [💬 Уточнить №N] → [✍️ Написать клиенту]. Ответ получает только клиент —
  другим мастерам он **не пересылается**.
- **Ответ клиента** на сообщение мастера приходит **только этому мастеру**.
- **История**: [💬 Уточнить №N] в `/orders` (или на карточке) показывает всю переписку по
  заказу — так остальные мастера видят, о чём договорились; [📎 Вложения] пересылает фото и файлы.
- Общие вопросы без заказа в историю заказа не попадают — только в журнал.
- История хранится вместе с заказом: переезжает при перенумерации и удаляется вместе с ним
  (в журнале `orders_history.log` переписка остаётся).

### Клиент редактирует заказ

Пока мастер **не выставил счёт** (статус «Принят, ждёт оценки»), клиент может изменить заказ:
«📦 Мои заказы» → [✏️ Изменить №N] → выбрать поле. Об этой возможности бот пишет клиенту сразу
после оформления.

- Печать: материал, слой, заполнение, цвет, файл модели. Разработка: описание, референсы
  (новый набор заменяет прежний, «Пропустить» — убрать все). Для всех: доставка (Европочта —
  с адресом ПВЗ), способ оплаты, ФИО, телефон (только кнопкой «Поделиться», только свой).
- Каждое изменение сохраняется сразу; **всем мастерам** приходит «✏️ Клиент изменил заказ №N:
  цвет: Белый → Чёрный» с кнопкой [📋 Карточка], карточки обновляются, новый файл или фото
  присылается следом. Изменение пишется в журнал.
- Если мастер успел выставить счёт, изменение не сохранится — клиенту предложат написать мастеру.

### Удаление заказов и номера

- **Выданный** заказ: на карточке готового заказа кнопка «📬 Выдан клиенту» (или «📬 Выдать №N»
  в `/orders`) → подтверждение → заказ сразу удаляется из базы.
- **Отклонённый** заказ хранится сутки, затем удаляется автоматически (проверка — раз в час).
- После любого удаления заказы **перенумеровываются без пропусков** (было 1, 2, 4 → стало 1, 2, 3).
  Карточки у мастеров обновляются с новыми номерами, клиенты получают сообщение
  «Номера ваших заказов обновились: №4 → №3», а незаконченное действие мастера
  (например, ввод суммы) по сдвинутому заказу сбрасывается — его нужно начать заново.
- Карточки, отправленные до появления этой функции, не обновляются — откройте свежие через `/orders`.

## База данных

Заказы хранятся в SQLite: `data/bot.db` (создаётся при первом запуске, в git не попадает).
Таблицы: `orders` — заказы, `admin_cards` — какие карточки заказов отправлены мастерам
(нужна, чтобы обновлять их у всех), `chat_messages` — переписка клиентов с мастерами по заказам.

### Журнал истории заказов

Все события по заказам (создан, счёт, оплачен, готов, отклонён, выдан и удалён, номер изменён,
сообщения клиенту) пишутся в текстовый файл `data/orders_history.log` — одна строка на событие.
Файл только дописывается, поэтому история сохраняется и после удаления заказа из базы.

```bash
tail -n 50 data/orders_history.log        # последние 50 событий
grep "Иванов" data/orders_history.log      # всё по клиенту
grep "| №3 |" data/orders_history.log     # всё, что происходило под номером 3
```

Номера заказов сдвигаются после удалений, поэтому один заказ в журнале может встречаться
под разными номерами — смена номера записана строкой «номер изменён: №5 → №4».

Открыть консоль базы:

```bash
sqlite3 data/bot.db
```

Полезные команды внутри консоли:

```sql
.headers on
.mode column
.tables                                          -- список таблиц
.schema orders                                   -- структура таблицы заказов
SELECT * FROM orders ORDER BY id DESC LIMIT 10;  -- последние 10 заказов
SELECT id, customer_name, phone, status FROM orders WHERE status = 'new';
.quit
```

Быстрый просмотр без входа в консоль:

```bash
sqlite3 -header -column data/bot.db "SELECT * FROM orders ORDER BY id DESC LIMIT 10;"
```

Для удобного просмотра в VS Code подойдёт расширение «SQLite Viewer» — откройте `data/bot.db`.
